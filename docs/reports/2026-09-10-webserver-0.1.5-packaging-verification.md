## 4. 本次修复的缺陷（均为容器启动阻断级）

### 4.1 P0-a：迁移 0005 校验和漂移（`checksum_mismatch` 崩溃）

- 现象：容器 `crash-loop`，日志 `checksum_mismatch for migration 0005`，`applied=7c3dad54…` vs `current=99837e3e…`。
- 根因：`ops_schema_migration_history` 记录 SQL 文件 sha256，启动时逐文件比对，不一致即崩溃。五环境库已应用 `e6467898` 修订版 0005（差异仅一行注释：`-- rollback: drop-web-application` → `-- rollback: down-migration`），而当前树仍是被回退前的旧版。**该校验和对字节敏感：LF 与 CRLF 变体哈希不同**（CRLF 变体为 `3f1acd0d…`，同样不匹配）。
- 修复：`git checkout e6467898 -- database/migrations/postgres/`（恢复 0005 up/down、新增 0007/0008 up/down + README），再 `sed -i 's/\r$//'` 统一 LF。回填后精确匹配线上已应用值：

```
0005_web_application.up.sql            = 7c3dad54eae056572c5165fdca77ec57bde92bf57b942a486470d04e283d1c56
0007_web_app_platform_target.up.sql    = 2f82f547220ced8e40679e719eeee99275765db13e50555d31fb3f9166fdfd5e
```

镜像内 `/app/database/migrations/postgres/` 同值复核通过。

> 教训：迁移文件的**行尾与注释**都是契约的一部分；任何"无害微调"都会让已在线上应用的库无法启动。

### 4.2 P0-b：入口脚本侧车路径参数错位（模块静态根完全不物化）

- 现象：development 升级后容器报
  `merged module-imports configuration failed: Web Server config failed validation (1 diagnostic(s)) /resources/7/root: directory /usr/share/sdkwork/account/web/pc is unavailable`。
- 根因：`deployments/docker/scripts/entrypoint-standalone.sh` 中 `materialize_module_web_static_roots()` 的调用漏传 `environment`。函数签名为 3 参：

  ```bash
  module_nginx_sidecar_abs_path(){ module_root=$1; environment=${2:-...}; profile=${3:-...}; \
    printf '%s/deployments/webserver/nginx.%s.%s.conf' "${module_root}" "${profile}" "${environment}"; }
  ```

  调用只传 2 参时 `${profile}` 落进第 2 位 → `environment` 退化为默认值 → 拼出的 `nginx.<env>.conf` 恒不存在 → `materialize_module_web_static_roots()` 一个模块都不物化 → 导入平面校验找不到 `/usr/share/sdkwork/<module>/web/pc`。
- 修复（单行，移植自 `e6467898`）：

```diff
-      conf="$(module_nginx_sidecar_abs_path "${module_root}" "${profile}")"
+      conf="$(module_nginx_sidecar_abs_path "${module_root}" "${environment}" "${profile}")"
```

该路径来自**启动时物化**（容器内 `/usr/share/sdkwork/account/web/pc` 软链到 `/opt/deploy/sdkwork-space/sdkwork-account/apps/sdkwork-account-pc/dist/cloud/test`），镜像本身并不含 `/usr/share/sdkwork/`——这也是为什么"镜像看起来正常但一启动就失败"。

### 4.3 CRLF 污染（目标机脚本直接退出 2）

- 现象：目标机 `deploy.sh: line 55: set: pipefail: invalid option name`（退出 2）。`\r` 不可见，MSYS 的 `sed/cat/grep` 管道会静默吞掉它，只有 WSL/Linux `bash` 会报错。
- 处置：全仓扫描跟踪脚本，修复 4 个 CRLF 脚本 + 5 个 `.env.example`，全部 `sed -i 's/\r$//'` 并以 `bash -n` 校验：

| 文件 | 修复前 CR | 修复后 |
| --- | --- | --- |
| `deployments/docker/bundle/deploy.sh` | 593 | 0 |
| `deployments/docker/scripts/entrypoint-standalone.sh` | 2133 | 0 |
| `deployments/docker/scripts/discover-module-hosts.sh` | 87 | 0 |
| `deployments/docker/scripts/install-wsl-hosts.sh` | 110 | 0 |
| `deployments/docker/env/*.env.example` ×5 | 146~195 | 0 |

镜像内 ENTRYPOINT 以 `docker create` + `docker cp` 提取复核：`CR=0`、shebang `#!/usr/bin/env bash`、`bash -n` OK。行尾判定统一用 `tr -cd '\r' < f | wc -c`。

## 5. 构建环境适配（DrvFs / 离线）

`/mnt/e`（9p/DrvFs）三个硬约束，均在 `bin/lib/module.sh` 中固化，不改 package.json 的规范入口：

1. **`SDKWORK_RELEASE_STAGE_PARENT` 必须指向 ext4**（本次 `/var/tmp/sdkwork-release-stage-015`）。DrvFs 不保留 POSIX 权限位，stage 目录会产出不可用上下文；另有一次因 0.1.4 时代遗留的 root 属主 stage 目录报 `EACCES … mkdir bin`，改路径即解。
2. **镜像构建绕开 pnpm**：`node_modules/.modules.yaml` 记录的是 Windows `storeDir`（`E:\.pnpm-store\v10`），在 9p 上 SQLite 不可用，`pnpm -v` 在仓库内即 `disk I/O error`。`sdkwork_image_build()` 改为直调 `node scripts/docker/build-standalone-image.mjs --tag <tag>`（与 `build:container:standalone` 同源），并透传 `SDKWORK_IMAGE_NO_PULL=1` → `--no-pull`（registry 不可达时 `docker build --pull` TLS 握手超时；复用已缓存基础镜像）。
3. **浏览器构建跨仓 TS 债**：`sdkwork-skills-pc-commons/src/runtime.ts(18,10) error TS2304: Cannot find name 'readRuntimeEnv'` 属兄弟仓债务。新增 `SDKWORK_BROWSER_SKIP_TYPECHECK=1` → `--skip-typecheck`（ENVIRONMENT_SPEC.md 认可），pc 20.73s / h5 710ms PASS；归档阶段用 `--skip-pc-build --skip-h5-build` 复用 step-1 产物，避免 `webserver-release.mjs` 内部二次构建失败。

另有一次**镜像内容残缺**（`/app` 仅 420M、`/opt/sdkwork/api-gateway/database-modules` 为空、缺 `sdkwork-intelligence-knowledgebase-rpc-bin`）：根因是并发的另一个会话正在构建 gateway 0.1.8，重建 `dist/container-image-build` 时被 staged 拷贝到半成品。等待其结束后核对目录结构与 59 个 database-modules 与 0.1.4 一致，再重建镜像，内容对齐。
